## 已检查但仍需关注的边界与优化

- 门禁检查的是网关会话，不是不可伪造的客户端身份：UA、客户端持有的 Cookie/签名密钥都不能证明未修改客户端。插件的 exam-client / _ncec 判断不能单独作为安全边界；HydroOJ 必须只监听本机。没有将此架构改造成可信执行或硬件证明系统。
- addon 的教师管理路由有 PERM_EDIT_CONTEST 检查；客户端文件读取已有 resolve/relative_to 限制。本次未修改插件 API，也未在真实 HydroOJ 中加载或编译插件。
- 本地服务仍对 loopback 免教师 JWT，并允许宽泛 CORS；应只在受控客户端运行环境使用。进一步收紧 Origin/Host 与 WebView 桥接授权需要联调现有打包前端，列为后续安全改进。
- 本地录像共享 HMAC 密钥随客户端分发，只能提供一致性检查，不能证明学生无法伪造录像。已纠正上传器说明中的过强保证。
- 关键帧失败只做一次短重试；不自动补传历史完整录像。网关重启需重新登录。进行中的旧上传与重新登录仍有短暂交叉可能，不能将当前实现视为完整持久上传队列。
- 上传统计按用户名与序号聚合，跨考试/客户端重启的序号重置可能影响缺口统计；需要独立考试会话 ID 的数据库/API 迁移，尚未实施。
- 数据库写入和部分文件操作仍在请求链路，50 台以上长期容量、数据库/上传目录增长和磁盘预算需实测。当前不自动删除服务端证据，考后归档由管理员操作。
- 当前静态前端只有构建产物，没有完整对应源码；未重写前端。下载目录 addon/public/exam 下存在旧客户端包，未覆盖它，部署时应替换为本次完整 dist/main.dist 压缩包，避免误发旧版。
- FastAPI on_event 有弃用提示，但当前测试可用；生命周期 API 迁移可单独进行。
