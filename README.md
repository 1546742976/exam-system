# HydroOJ + Veyon 轻量监考方案

面向约 100 人的局域网编程考试，保留系统浏览器答题，将考试业务与屏幕监看分开。优先复用 Veyon 的采集、认证与连接能力，不再从零开发 Rust 截图客户端。

> 当前已建立 TypeScript 插件、Veyon 源码快照、采集工具和自动化测试。真实 Veyon/NUC/无线考场验收尚未完成；运行方式见 deploy/README.md，测试证据见 reports/。

## 1. 系统组成

| 部分 | 技术与部署位置 | 职责 |
|---|---|---|
| 考试平台 | NUC：HydroOJ | 账号、比赛、题目、提交、评测 |
| 监考插件 | NUC：TypeScript，复用 HydroOJ | 考试与设备绑定、定时采样、状态、截图索引、教师权限 |
| 采集服务 | Windows：Veyon Service + 本机 WebAPI | 屏幕采集、认证，返回压缩截图 |
| 学生答题 | Windows：系统浏览器 | 登录并参加考试 |
| 教师界面 | HydroOJ 模板与 TypeScript | 状态列表、历史图片、按需抽查 |
| 存储 | NUC：MongoDB + 本地图片目录 | 元数据入库，图片按考试归档 |

```text
学生浏览器 ──考试请求──────────→ HydroOJ（NUC）
                                    │
教师浏览器 ──监考页面──────────→ 监考插件
                                    │ 主动请求、认证
                                    ▼
                         学生电脑 Veyon WebAPI
                                    │ 本机连接
                                    ▼
                             Veyon Service
                                    │ 压缩图片响应
                                    ▼
                              NUC 图片目录
```

采用 Veyon WebAPI 的 Local 模式：图片在学生电脑侧处理后传给 NUC。Proxy 模式若部署在 NUC，缩小 HTTP 返回图片不能证明学生到 NUC 的底层屏幕传输也变小，因此不作为低带宽默认方案。

Veyon Master 保留为管理员联调或临时人工查看工具，考试期间不同时打开全班实时画面墙。无需独立 Python 网关、内嵌浏览器或视频编码链路。

## 2. 复用范围与需要开发的部分

Veyon 已有屏幕查看、截图、认证和 WebAPI；WebAPI 支持 JPEG、质量与输出宽高参数。它本身不提供本项目完整的考试身份绑定、定时归档和保留期限管理。

本项目 HydroOJ 插件功能：

- 导入座位、设备标识和固定地址清单；教师确认学生账号与设备的对应关系，不仅凭来源 IP 自动认定身份。
- 按考试启停采样，记录最近成功连接时间、最近截图时间和具体错误。
- 定时取图、教师即时抽查、图片历史和考后 7 天清理。
- 限制教师只能访问其有权限管理的考试；只连接预先登记的设备地址。

第一阶段覆盖连接异常、截图失败与屏幕抽查。原方案要求的多屏变化及指定进程告警仍是后续需求，不能宣称 Veyon 截图接口已提供：须先核实可用扩展接口，再决定是否增加小型检测组件。第一阶段不为此新增 Python 或 Rust 常驻程序。

## 3. 低资源采样策略

| 项目 | 初始配置目标 |
|---|---|
| 定期采样 | 独立均匀抽取 30,001～89,999 毫秒，计划间隔期望 60 秒 |
| 启动速率 | 全局令牌桶每秒补充 2 个令牌，容量 2 |
| 图片接收预算 | 全局共享 250,000 字节/秒（2 Mbit/s），突发额度 32 KiB |
| 常规图片 | 宽度上限 1280 像素，JPEG 质量 55 |
| 教师抽查 | 宽度上限 1920 像素，JPEG 质量 65 |
| 并发取图 | 全局最多 4 台，每设备最多 1 个请求 |
| 单次采样超时 | 实际启动后整个任务最多 10 秒，不含排队等待 |
| 失败处理 | 本轮记失败，下轮重试；不积压历史任务 |
| 异常状态 | 区分调度延迟、采集失败与连接不可达；连续三次连接不可达才显示持续不可达 |
| 图片保留 | 考试结束后 7 天，每小时分批清理 |
| 教师页面 | 每 15 秒刷新状态；仅加载展开的图片 |

这是随机周期采样，不等于原方案的 15 秒客户端主动心跳。限流优先，允许实际检测延迟并记录。界面同时显示“最后联系时间”和“最后截图时间”，不把网页在线等同于采集服务正常，也不能把排队误报为学生断线。

### 随机调度与有界任务

- 每次由服务端独立均匀抽取整数 30,001～89,999 毫秒，共 59,999 个等概率取值，不向学生端公布下一次计划时间。
- 期望为 `(30,001 + 89,999) / 2 = 60,000` 毫秒，严格落在 `(30,90)` 秒内。有限次数的样本平均值不保证恰好为 60 秒。
- 首次周期检测采用相同分布；开考前设备检查独立处理。
- 后续计划时间以**上一计划时间**累加随机间隔，不以任务完成时间累加，避免下载耗时改变计划间隔的期望。
- 每设备最多一个执行中任务和一个待执行任务；多个周期到期时合并待执行任务，保留最早到期时间并记录合并次数，不补跑历史截图。
- 教师抽查不重置周期计划，同设备已有待执行任务时合并为一次抽查，并保留原先最早到期时间。
- 调度使用单调时钟；服务重启后重新随机安排，不补偿停机期间任务。界面另记录可读时间，不将单调时钟数值当作日期。
- 按任务最早到期时间分配启动令牌与并发名额，教师抽查共用限额，不插队绕过限制。

数学期望 60 秒只适用于计划间隔。实际启动间隔与成功截图间隔分别统计，不承诺其均值仍为 60 秒。

### 图片接收限流

- 所有图片响应共用一个字节令牌桶，补充速率为 250,000 字节/秒，容量为 32,768 字节，不为每台设备分别发放完整带宽。
- 采用流式背压读取，在预算允许时读取对应字节数；不得先完整下载，再通过延迟保存伪装限速。
- 任意时长为 `t` 秒的窗口，应用层读取量不得超过 `250,000 × t + 32,768` 字节。突发额度意味着短窗口速率可能高于 2 Mbit/s。
- 该预算不含 TLS/TCP 开销，无法消除系统缓冲或无线链路瞬时突发，不是网卡级硬上限。
- 队列等待不计入 10 秒任务超时；启动后的认证、等待画面、限速读取与保存均计入任务时间。超时关闭连接，释放名额并记录失败，不保留不完整图片为有效截图。
- 教师读取已保存图片不计入采集预算；HydroOJ 答题与提交不经过图片限速器。

### 状态记录

每次执行记录计划时间、实际启动时间、完成时间、排队延迟、接收字节数、超时原因和合并周期数。计划时间不通过学生接口公开。排队时间使用单调时钟差值计算；成功截图和失败尝试分开计数。持续积压时报告容量不足，不自动提高带宽或并发限制。

每轮连接、认证、等待有效画面、取图后主动关闭连接，以限制 NUC 同时保留的帧缓冲；首次有效画面的准备耗时与短连接成本必须实测。不能把初始化黑帧判定为有效截图，也不能仅凭画面全黑判定作弊。

请求取图时使用 WebAPI 的 JPEG、quality 和 width/height 参数，仅设置 width 限制宽度并保持比例，竖屏高度可能超过该数值。接口不提供按字节硬限制的保证；100 KiB 只是常规图片的容量预算。复杂画面超出预算时，不立即重复取图，先记录大小用于调参。

NUC 流式保存返回图片，不再次解码、缩放或转码。每请求设置 2 MiB 接收上限，超限中止并告警。图片索引保存考试、学生、设备、请求时间、接收时间、触发原因和大小；没有可靠客户端采集时间时，不将接收时间标为采集时间。

## 4. 部署与认证

- 学生端安装受支持的 Veyon 版本，启用 Local WebAPI 与 HTTPS；按官方方式配置每台设备的证书，NUC 校验服务器证书，不关闭证书校验。
- 使用 Veyon 支持的密钥认证。每设备采用独立密钥，私钥文件保存在 NUC 受限目录、公钥配置到对应学生端。AuthKeys WebAPI 认证会将 PEM 私钥发送到该学生端，因此必须验证 HTTPS 身份，禁止全考场共享管理私钥。
- 防火墙仅允许 NUC 访问学生端 WebAPI；不向普通学生或公网开放管理接口。
- 使用固定地址或 DHCP 保留，考前验证 NUC 能主动访问学生设备；无线隔离策略不得阻断此路径。
- 只调用连接管理、状态及 framebuffer 接口，不通过监考插件开放远程控制、关机或文件操作。
- 浏览器不持有 Veyon 管理密钥，也不直连学生电脑。照片通过 HydroOJ 权限检查后读取。
- 开考前检测截图和身份映射；考试中采样故障告警但不自动阻止提交。

## 5. 负载预算与验收

若每张图平均 100 KiB、100 人计划间隔期望 60 秒，图片响应长期平均约为 1.37 Mbit/s，3 小时容量预算约为 1.72 GiB；随机波动、排队合并和失败会影响实际张数。该估算不含认证、连接建立、协议开销、教师查看及额外抽查流量，必须测量实际网络数据。

100 台设备的理论平均需求约为每秒 1.67 次，每秒 2 次启动额度仅有少量余量。全局 4 并发要持续跟上，平均任务耗时需低于约 2.4 秒；若每次都达到 10 秒超时，最多每秒处理约 0.4 台，无法满足目标。2 Mbit/s 虽高于上述常规图片平均预算，大图片、额外抽查和慢设备仍可能导致延迟。

降低学生端输出分辨率有助于减少传输和 NUC 存储。若上传原图后才在 NUC 缩小，不会减少此前的无线流量，还会增加 NUC 图像处理工作。

不沿用自研 Rust 程序的 20 MiB 内存承诺。Veyon 包含服务、采集后端及 WebAPI，须统计学生端全部相关进程；同样要统计 NUC 上插件增量内存和连接处理开销。

验收顺序：

1. 单机验证认证、首次有效帧、1080p/4K、锁屏、断网和证书错误。
2. 10 台实机比较每轮重连与短期复用连接的 CPU、内存、流量和取图时延；若改变默认连接策略，先更新本文并重新测试。
3. 使用可控时钟验证严格随机范围、计划时间累加、重启、周期合并、教师抽查及无历史补跑；期望通过离散均匀分布公式证明，抽样仅作辅助。
4. 验证启动令牌桶、全局 4 并发、单设备 1 并发、共享字节预算和任务超时释放。100 台模拟覆盖正常图片、大图片、慢响应、断网和集中抽查，确认队列有界且延迟可见。
5. 实际无线考场连续运行 3 小时，同时进行 HydroOJ 登录、提交和评测；分别测量应用读取速率和网卡流量，确认协议与缓冲差异，确认提交不受图片限速器影响。模拟接口负载不替代无线实测。
6. 核实图片能辨认应用与主要内容、教师权限隔离、学生设备映射、采样故障展示和文件清理。

若实际调度持续延迟，或 Veyon 实际流量超出考场预算，报告测量结果和容量不足，不自动提高用户选定的 2 Mbit/s 预算。不能把 HTTP 图片大小当作整体低负载证明。

代码已实现上述调度与传输模块；测试与模拟报告不能替代真实 Veyon、浏览器 HTTP 流程和考场验收。
