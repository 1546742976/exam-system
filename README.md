# HydroOJ + Veyon 轻量监考方案

面向约 100 人的局域网编程考试，保留系统浏览器答题，将考试业务与屏幕监看分开。优先复用 Veyon 的采集、认证与连接能力，不再从零开发 Rust 截图客户端。

> 当前为设计文档，尚未实现集成或完成性能验收。工作区目前没有原项目源码；实施前需恢复并确认源码版本。

## 1. 系统组成

| 部分 | 技术与部署位置 | 职责 |
|---|---|---|
| 考试平台 | NUC：HydroOJ | 账号、比赛、题目、提交、评测 |
| 监考插件 | NUC：TypeScript，复用 HydroOJ | 考试与设备绑定、定时采样、状态、截图索引、教师权限 |
| 采集服务 | Windows：Veyon Service + 本机 WebAPI | 屏幕采集、认证，返回压缩截图 |
| 学生答题 | Windows：系统浏览器 | 登录并参加考试 |
| 教师界面 | HydroOJ 模板与 TypeScript | 状态列表、历史图片、按需抽查 |
| 存储 | NUC：MongoDB + 本地图片目录 | 元数据入库，图片按考试归档 |

```text
学生浏览器 ──考试请求──────────→ HydroOJ（NUC）
                                    │
教师浏览器 ──监考页面──────────→ 监考插件
                                    │ 主动请求、认证
                                    ▼
                         学生电脑 Veyon WebAPI
                                    │ 本机连接
                                    ▼
                             Veyon Service
                                    │ 压缩图片响应
                                    ▼
                              NUC 图片目录
```

采用 Veyon WebAPI 的 Local 模式：图片在学生电脑侧处理后传给 NUC。Proxy 模式若部署在 NUC，缩小 HTTP 返回图片不能证明学生到 NUC 的底层屏幕传输也变小，因此不作为低带宽默认方案。

Veyon Master 保留为管理员联调或临时人工查看工具，考试期间不同时打开全班实时画面墙。无需独立 Python 网关、内嵌浏览器或视频编码链路。

## 2. 复用范围与需要开发的部分

Veyon 已有屏幕查看、截图、认证和 WebAPI；WebAPI 支持 JPEG、质量与输出宽高参数。它本身不提供本项目完整的考试身份绑定、定时归档和保留期限管理。

需要开发的 HydroOJ 插件功能：

- 导入座位、设备标识和固定地址清单；教师确认学生账号与设备的对应关系，不仅凭来源 IP 自动认定身份。
- 按考试启停采样，记录最近成功连接时间、最近截图时间和具体错误。
- 定时取图、教师即时抽查、图片历史和考后 7 天清理。
- 限制教师只能访问其有权限管理的考试；只连接预先登记的设备地址。

第一阶段覆盖连接异常、截图失败与屏幕抽查。原方案要求的多屏变化及指定进程告警仍是后续需求，不能宣称 Veyon 截图接口已提供：须先核实可用扩展接口，再决定是否增加小型检测组件。第一阶段不为此新增 Python 或 Rust 常驻程序。

## 3. 低资源采样策略

| 项目 | 初始配置目标 |
|---|---|
| 定期采样 | 每台每 60 秒一次，按设备错峰 |
| 常规图片 | 最长边 1280 像素，JPEG 质量 55 |
| 教师抽查 | 最长边 1920 像素，JPEG 质量 65 |
| 并发取图 | 全局最多 4 台，每设备最多 1 个请求 |
| 单次采样超时 | 整个任务最多 10 秒 |
| 失败处理 | 本轮记失败，下轮重试；不积压历史任务 |
| 异常状态 | 一次失败显示采样失败；连续三轮失败显示持续不可达 |
| 图片保留 | 考试结束后 7 天，每小时分批清理 |
| 教师页面 | 每 15 秒刷新状态；仅加载展开的图片 |

这是一分钟采样状态，不等于原方案的 15 秒客户端主动心跳。界面同时显示“最后联系时间”和“最后截图时间”，不把网页在线等同于采集服务正常。

每轮连接、认证、等待有效画面、取图后主动关闭连接，以限制 NUC 同时保留的帧缓冲；首次有效画面的准备耗时与短连接成本必须实测。不能把初始化黑帧判定为有效截图，也不能仅凭画面全黑判定作弊。

请求取图时使用 WebAPI 的 JPEG、quality 和 width/height 参数，按画面方向限制最长边并保持比例。接口不提供按字节硬限制的保证；100 KiB 只是常规图片的容量预算。复杂画面超出预算时，不立即重复取图，先记录大小用于调参。

NUC 流式保存返回图片，不再次解码、缩放或转码。每请求设置 2 MiB 接收上限，超限中止并告警。图片索引保存考试、学生、设备、请求时间、接收时间、触发原因和大小；没有可靠客户端采集时间时，不将接收时间标为采集时间。

## 4. 部署与认证

- 学生端安装受支持的 Veyon 版本，启用 Local WebAPI 与 HTTPS；按官方方式配置每台设备的证书，NUC 校验服务器证书，不关闭证书校验。
- 使用 Veyon 支持的密钥认证。私钥只保存在 NUC 受限目录，公钥配置到学生端；认证字段与连接流程以锁定版本的官方 API 为准。
- 防火墙仅允许 NUC 访问学生端 WebAPI；不向普通学生或公网开放管理接口。
- 使用固定地址或 DHCP 保留，考前验证 NUC 能主动访问学生设备；无线隔离策略不得阻断此路径。
- 只调用连接管理、状态及 framebuffer 接口，不通过监考插件开放远程控制、关机或文件操作。
- 浏览器不持有 Veyon 管理密钥，也不直连学生电脑。照片通过 HydroOJ 权限检查后读取。
- 开考前检测截图和身份映射；考试中采样故障告警但不自动阻止提交。

## 5. 负载预算与验收

若每张图平均 100 KiB、100 人每分钟一张，图片响应约为 1.37 Mbit/s，3 小时约占 1.72 GiB。该估算不含认证、连接建立、协议开销、教师查看及额外抽查流量，必须测量实际网络数据。

降低学生端输出分辨率有助于减少传输和 NUC 存储。若上传原图后才在 NUC 缩小，不会减少此前的无线流量，还会增加 NUC 图像处理工作。

不沿用自研 Rust 程序的 20 MiB 内存承诺。Veyon 包含服务、采集后端及 WebAPI，须统计学生端全部相关进程；同样要统计 NUC 上插件增量内存和连接处理开销。

验收顺序：

1. 单机验证认证、首次有效帧、1080p/4K、锁屏、断网和证书错误。
2. 10 台实机比较每轮重连与短期复用连接的 CPU、内存、流量和取图时延；若改变默认连接策略，先更新本文并重新测试。
3. 100 台模拟调度验证错峰、并发上限、超时、任务不积压和文件清理。
4. 实际无线考场连续运行 3 小时，同时进行 HydroOJ 登录、提交和评测；模拟接口负载不替代无线实测。
5. 核实图片能辨认应用与主要内容、教师权限隔离、学生设备映射、采样故障展示。

若 4 并发无法在一分钟内覆盖 100 台，或 Veyon 实际流量超出考场预算，先报告测量结果并调整方案，不能把定期 HTTP 图片大小当作整体低负载证明。
